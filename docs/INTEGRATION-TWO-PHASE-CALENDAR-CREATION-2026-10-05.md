# Opt-in two-phase race creation in the isolated preview

An administrator can now select a separate tactics deadline when creating a scheduled one-day race, provided automatic entry processing is enabled. Registration closes at the existing entry deadline; the tactics deadline must follow the next 02:00 UTC daily scan by at least 70 minutes and precede the scheduled race. The existing one-deadline creator remains the default. Both gender events use the same opted-in dates, and a repeated request returns the same event IDs. The administrator's race-run button stays disabled until the scheduled start for these events.

Migration `20261005093442_opt_in_two_phase_calendar_creation.sql` adds only a service-role creator that wraps the safe scheduled creator. It was applied **only** to isolated Supabase project `nxhvaoonnvmvohqaxfdx`. The rollback-only `tests/support/two-phase-calendar-creation-probe.sql` checked both saved gender events, idempotent retry, changed-request rejection, invalid-window rejection and fixture rollback. The security and performance advisors reported no new findings caused by this function. The existing private-table RLS/no-policy and older index notices remain. No production database or deployment changed. This closes an event-creation gap, but the two-phase milestone still needs a full real manager-to-simulator-to-replay test.
